● 我已定位问题。看日志和你的配置，当前还没有任何 Gemini provider 被写入 —— 只看到
  OpenClaw 类型的 ofoxai/ofoxai1。问题根源很清晰：

  核心原因

  Claude Code 用的是 Anthropic Messages API 协议，Gemini 用的是 Google
  自己的协议——两者不兼容。直接把 Gemini 官方 API 的 URL/Key 填进 CC-Switch
  一定失败，因为协议层就不匹配。

  接入"第三方 Gemini"的唯一可行路径是：通过一个支持 Anthropic
  协议转换的中转站（你现在用的 ofox.io 就是这种聚合站）。

  诊断你当前的配置

  ANTHROPIC_BASE_URL: https://api.ofox.io/anthropic   ✅ 路径含 /anthropic 说明走转换
  ANTHROPIC_AUTH_TOKEN: sk-of-ct...                    ✅ 是 ofox 的 key

  ofox 这条线本身是通的（你已经在用 Claude）。接入 Gemini
  失败的真正原因，多半是下面三种之一：

  三种最常见的失败原因 + 解决

  ① 模型名写错（出现频率 80%）

  CC-Switch 里新建一个 Provider，"模型 Model" 字段不能写 gemini-2.5-pro 或
  gemini-pro——Claude Code 在请求体里发的是 claude-*
  系列模型名。必须由中转站做模型映射。

  解决：在 ofox.io 的网页后台 → 模型映射 / 路由规则 里，把 claude-opus-4-7 或
  claude-sonnet-4-6 映射到 gemini-2.5-pro。然后 CC-Switch 里模型字段仍然填

  Claude Code 发出的请求结构是这样的：
  {

      { "role": "user",      "content": "..." }
    ]
  }

  - Anthropic 协议：允许 system 作为独立字段或消息角色 ✅
  - Gemini 协议：只认 user 和 model（部分兼容层接受 assistant），绝不接受 system ❌

  ofox 把请求"形式上"接住了（端点路径对了），但没把 system role 合并进 user就直接丢给
  Gemini，于是 Gemini 原生 400。
