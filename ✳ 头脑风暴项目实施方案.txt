  一、声音的桥 Bridge of Voices

  当前状态

  代码完整（26文件），功能齐全，但PWA图标未生成，LLM
  只接了抽象层。

  要做什么（按优先级）

  P0 — 立刻能做
  1. 生成 PWA 图标 — 在浏览器打开
  generate-icons.html，一键生成 8 种尺寸 PNG，PWA
  才能正常安装
  2. 接入真实 LLM — llm-client.js 已经写好了
  OpenAI/Anthropic 的适配层，填个 API Key
  就能让"正则兜底"升级为"LLM理解复杂叙述"

  P1 — 核心增强
  3. 方言语音识别 — speech.js 已预留方言扩展点。Web
  Speech API
  本身不支持方言，但可以接入阿里云/腾讯云的方言
  ASR（四川话、河南话、粤语），在 speech.js 里加一个
   provider 切换
  4. 合同扫描翻译 —
  加一个拍照→OCR→白话解释的功能。用 firecrawl_parse
  或本地 OCR 库把劳动合同扫描成文字，再用 LLM
  翻译成大白话
  5. 访谈问题持续优化 — interview-questions.json
  里的问题树可以继续丰富，尤其是"混合型纠纷"（同时欠
  薪+无合同的情况）

  P2 — 平台化
  6. 微信小程序版本 — 当前是纯 Web
  PWA，如果能打包成小程序，对工人群体更触手可及

  巧思

  - "不说法律术语"原则要贯彻到底 — 当前 templates.js
   的法条引用有点生硬。更好的做法：先给大白话结论，
  再附法条原文（小字、可折叠）。劳动者不需要被法律术
  语吓到
  - 证据清单要"傻瓜化" —
  不只是列出"需要工资条"，而是告诉用户"打开微信→我→
  服务→钱包→账单→截图"，给操作路径
  - 恐惧指数 —
  在访谈最后加一个隐性的"恐惧指数"评估（是否有报复威
  胁、是否被威胁），如果指数高，在生成的文档中特别标
  注"注意人身安全"，并在行动指南中给出法律援助热线

  二、风信标 Windvane

  当前状态

  原型完整（10文件），GPS
  模拟模式可跑，深色骑行主题。

  要做什么（按优先级）

  P0 — 立刻能做
  1. 补齐城市风险区域数据 — risk-zones.json 只有深圳
   3 个 + 北京 1 个。每个城市至少需要：电动车事故高
  发路口、交警常驻点、修车铺位置、可休息的公共空间
  2. 后台持续监测 — 当前切到后台就停了。需要 Service
   Worker +
  后台定位（navigator.geolocation.watchPosition 在
  Web 的限制较大，原生 APP 更合适）

  P1 — 核心增强
  3. 申诉辅助真正可用 — appeal-helper.js
  生成的文本是模板化的。需要接入 LLM（复用
  bridge-of-voices 的 llm-client.js），根据实际行程
  数据生成有说服力的申诉文本
  4. 安全评分可视化 — analytics.js
  已经算了安全评分，但没有可视化展示。加一个 Canvas
  绘制的"骑行热力图"，把急刹/超速点标在地图上
  5. 充电站 + 修车铺地图 — 这是骑手最需要的实用信息
  。可以手动维护数据，也可以爬取高德/百度地图 POI

  P2 — 平台化
  6. 从 Web 走向原生 APP — 后台定位、传感器实时监测
  在浏览器里都很受限。可以考虑 React Native 或
  Flutter 重写

  巧思

  - "幽灵骑手"模式 —
  不只是记录自己的数据。当某个路口有多位骑手都出现急
  刹，说明那里有问题。不需要上传个人数据，只需要上传
  匿名化的风险标记（路口坐标+事件类型），类似于 Waze
   的众包模式
  - "反算法"仪表盘 — 不只显示速度，而是显示"你刚才为
  了不超时，付出了多少安全代价"。比如："这一单你闯了
   2 个黄灯，多赚了 3 块钱，但事故风险提升了
  12%"。让隐性代价显性化
  - 语音日记 —
  骑行中不方便打字，一键录音："今天XX小区保安又刁难
  了"，自动转文字+时间戳+位置，积累成"骑手生存档案"

  三、铁脊柱 Iron Spine

  当前状态

  Web 配置器完整，designs/ 目录的 3 个 SVG
  设计图缺失，没有任何实物原型。

  要做什么（按优先级）

  P0 — 立刻能做
  1. 生成 3 张 SVG 设计图 — design-viewer.js 已经用
  Canvas 画了技术图。但可下载的印刷模板 SVG
  还是空白。需要直接在 designs/ 下创建：
    - back-support.svg：背撑模块的 1:1
  打印模板（含钻孔位置标记）
    - knee-support.svg：膝撑模块铰链定位图
    - shoulder-support.svg：肩撑模块绑带走线图
  2. 完善物料清单 — bom-generator.js
  的淘宝关键词很好，但可以更精确：给具体链接或至少给
  精确的搜索词（如"玻纤板 3mm
  50cmx30cm"而不是"玻纤板"）

  P1 — 核心增强
  3. 身体参数→STL 3D 模型生成 — 当前只有 2D Canvas
  图。如果能根据身体参数自动生成可 3D 打印的 STL
  文件（连接件、铰链、卡扣），就真正实现了"开源制造"
  。可以用 OpenSCAD（参数化建模语言）在浏览器里生成
  4. 组装视频脚本 — build-guide-zh.md 写得很好，但视
  频比文字更直观。可以写一个分镜脚本，然后拍/渲染
  5. 实物原型制作 — 这是最关键的一步。按自己的物料清
  单采购，实际做一套，测试、拍照、改进

  P2 — 社区化
  6. 使用者反馈系统 — 一个简单的表单：穿了多久、哪里
  不舒服、坏了哪里、改进建议

  巧思

  - "废品站 BOM"分支 — 当前 BOM
  是基于淘宝新材料的。可以维护一份"纯废品站
  BOM"：用旧自行车内胎代替弹力绳、用废 PVC
  管代替玻纤板。成本从 200 降到 20，虽然性能降
  30%，但对于经济最困难的人可能是唯一选择
  - "反向人体工学"设计 —
  不只看身高体重，还要看工作姿势。搬砖工和快递分拣员
  的弯腰模式完全不同。configurator.js
  的姿势参数可以更细化：长时间静态弯腰 vs
  频繁快速弯腰，弹力绳预张力应该不同
  - "修复优先于制造" — 在 build-guide-zh.md
  里加一章"常见损坏和修复"：弹力绳断了怎么换、卡扣裂
  了怎么用扎带临时替代。因为对于使用者来说，坏了好修
  比好看更重要
  - 零电子元件不意味着零传感器 — 可以在关键应力点贴
  变色应力指示贴纸（廉价的光学应变片），当受力过大时
  变色，使用者一眼就能看到"这里快坏了"
